# 后端审查整改设计

日期：2026-08-31

## 目标

在保持现有 FastAPI 路由和前端调用方式基本不变的前提下，修复本次后端审查发现的权限越界、成绩完整性、导入幂等和稳定性问题。

本次实现范围：

1. 普通用户只能查看个人排行数据；部门管理员只能查看本部门及子部门；超级管理员查看全局数据。
2. 排行统计只纳入已发布的正式考试成绩，不纳入模拟考试或未发布成绩。
3. 已发布/进行中的考试禁止修改影响作答和评分的核心规则。
4. 每个考试会话保存自己的选项打乱映射，提交时还原答案后判分。
5. 严格拒绝空白或与选项不匹配的题目答案结构。
6. 预览 token 改为 SQLite 持久化、一次性原子消费，并绑定操作者和过期时间。
7. 增加请求大小、导入、限流、统计查询和异常处理方面的防护。

## 非目标

- 不迁移 PostgreSQL，不引入 Redis 作为强制依赖。
- 不重写前端页面和现有 API 路径。
- 不修改三个可选 Nit：默认 CORS 策略、初始化日志输出方式、缺少 JWT 密钥时的启动策略；这些作为后续运维改进单独处理。
- 不做与本次审查无关的全量代码风格重构。

## 设计原则

- 先写回归测试，再改生产代码。
- 业务权限在 service 层再次校验，路由层只做依赖注入和基础参数校验。
- 所有一次性动作使用数据库条件更新保证幂等。
- 预览数据和 token 的生命周期由数据库控制，不依赖单进程内存。
- 保持现有响应字段；新增字段只用于内部持久化或兼容性增强。

## 方案一：权限与统计

### 排行权限

`GET /api/rank` 保留现有路径和查询参数：

- `role=user`：只返回当前用户自己的统计；`scope=group` 也不允许扩展到全局用户。
- `role=dept_admin`：只返回其 `dept_group_id` 子树内用户；分组排行也只聚合这些分组。
- `role=super_admin`：返回全量排行。

`stats_service.rank()` 增加调用者范围参数，优先使用 SQL 子查询过滤用户，避免把大批用户 ID 拉到 Python 后再拼 `IN`。

### 成绩统计

`refresh_daily()` 聚合考试成绩时 JOIN `exam_definitions`，并限定：

```sql
exam_definitions.type = 'formal'
AND exam_results.published = 1
```

这样模拟考试和待复核/待公布成绩不会进入考试均分、考试次数和排行榜。

### 管理端概览

部门管理员的题目数、完成率、考试数、答题数、复核数和活跃数统一使用同一份 scope 规则。考试范围采用“考试全部指派分组均在 scope 内”的口径，与考试列表、成绩列表保持一致。

## 方案二：考试完整性

### 状态机

允许的核心状态转换：

```text
draft -> published -> ongoing -> ended
                         \-> reviewing -> ended
```

实现上不强制新增状态迁移任务，而是在 service 层增加守卫：

- `draft` 才允许修改题目来源、题目清单、时长、及格线、分组和评分开关。
- `published/ongoing/reviewing/ended` 只允许修改不影响历史成绩的展示名称（如确有需要）。
- 已存在会话或成绩时，禁止重新发布或改变核心规则。
- 发布前必须验证题目引用、模板引用、时间格式、时间先后和试卷非空。

### 会话级选项打乱

在 `ExamSession` 增加 `shuffle_maps` JSON 字段，结构为：

```json
{
  "question_id": {
    "A": "C",
    "B": "A",
    "C": "B"
  }
}
```

开考时根据会话随机源为单选、多选题生成映射并保存；`session_payload()` 返回按映射重排后的选项，但仍使用前端现有 A/B/C 字母交互。交卷时使用反向映射把用户答案还原到题库答案坐标后调用 `grade()`。判断、填空、简答和拖拽题不改变现有语义。

旧会话若 `shuffle_maps` 为空，则首次读取时生成并保存兼容映射；已经提交的会话不再修改。

## 方案三：导入预览 token

### 数据模型

新增 `ImportPreview` 模型和表，字段：

- `id`
- `token_hash`：原 token 的 SHA-256，唯一索引
- `kind`：`question` 或 `user`
- `owner_id`：创建预览的管理员用户 ID
- `payload`：JSON 预览数据
- `created_at`
- `expires_at`
- `consumed_at`：一次性消费时间，可为空

前端仍接收随机 `secrets.token_urlsafe(32)` 原 token；数据库只保存哈希。

### 用户导入密码

用户导入预览时立即对初始密码执行 bcrypt 哈希，token payload 只保存 `password_hash`，确认导入时不再保存或重新传输明文密码。

### 原子消费

确认导入时在事务中执行条件更新：

```sql
UPDATE import_previews
SET consumed_at = :now
WHERE token_hash = :hash
  AND owner_id = :owner_id
  AND consumed_at IS NULL
  AND expires_at > :now
```

只有更新行数为 1 的请求可以继续导入；其他并发请求返回“预览已消费或已过期”。导入失败时保留失败日志，但 token 不允许重复消费，避免重复导入。

增加过期记录清理函数，在预览创建和启动维护时执行；必要时提供一次性迁移脚本。

## 输入、稳定性和性能

1. `ExamAnswerIn.answer`、草稿 payload、题目规则和上传预览增加字节数/嵌套深度限制。
2. Excel 解析放入线程池，避免同步 openpyxl 阻塞 async 事件循环。
3. 答题、草稿、标记接口增加用户级限流；现有认证/上传限流保留。
4. 用户邮箱统一 `strip().lower()`，增加大小写不敏感唯一约束迁移。
5. 用户分组 ID、考试题目 ID、模板 ID 在写入前显式验证，错误返回 400/403，不让外键异常变成 500。
6. 排行、统计和范围过滤改用 JOIN/子查询，减少 N+1 和超大 `IN` 列表。
7. `_streak()` 使用传入的日期范围。
8. 审计日志改为由调用方控制事务；在路由可取得时传入脱敏后的客户端 IP。

## 错误处理

- token 不存在、过期、归属不符或已消费统一返回明确的 400/403，不泄露其他用户的 payload。
- 已发布考试修改返回 409，避免被误认为参数错误。
- 非法题目答案、非法引用和时间配置返回 400。
- Excel 解析异常统一转换为 400，并确保数据库事务回滚。
- 并发版本冲突继续返回现有 409 语义。

## 测试方案

新增或补充以下测试，全部先建立 RED 再实现：

1. 普通用户只能看到自己的排行；部门管理员看不到其他部门排行；超级管理员可看全量。
2. 未发布正式成绩和模拟成绩不会进入排行。
3. 部门概览所有指标都按 scope 过滤，混合分组考试口径一致。
4. 同一个导入 token 并发确认只有一次成功；不同用户不能消费；过期 token 不能消费。
5. 已发布/进行中的考试修改核心规则返回 409；草稿仍可修改。
6. 单选/多选会话选项打乱后，提交显示字母仍能正确判分。
7. 空白填空答案、空白拖拽映射和超出选项范围的答案被拒绝或判错。
8. 超大答案/草稿、非法分组 ID、非法 Excel 角色状态得到预期 4xx。
9. `_streak()` 在 7d/30d/all 范围内结果正确。
10. 上传解析在线程池执行，不阻塞事件循环的行为通过可测试的封装验证。

现有 92 个测试、Ruff、MyPy 作为回归基线；覆盖率需要补装 `pytest-cov` 后再执行。

## 迁移与发布

1. 先新增模型和迁移脚本，保证旧数据库可以增量升级。
2. 迁移前备份 SQLite 主库、WAL 和 SHM 文件。
3. 先部署兼容读取逻辑，再启用新的 token 写入和会话 shuffle 字段。
4. 迁移完成后运行完整测试和一次手动导入/开考/交卷冒烟。
5. 不修改现有路由路径，前端只需兼容后端返回的重排选项。

## 验收标准

- 所有 Critical 回归测试通过。
- 现有测试全部通过。
- `ruff check`、`ruff format --check`、`mypy` 通过。
- 不再出现跨部门排行/概览数据、重复导入、已发布考试规则被覆盖或空答案得分。
- SQLite 旧库可完成迁移，单 worker 和多 worker 均可消费导入 token。
